# v0.2 depth preparation implementation

**Status:** Implementation in progress; real-corpus evidence is pending.

The Python depth worker now exposes `still-shift-depth prepare` and
`still-shift-depth contact-sheet`. The preparation pipeline normalizes supported source
images (EXIF orientation, sRGB conversion, white alpha compositing, and 2048-pixel
maximum edge), hashes canonical normalized RGB pixels, estimates depth, and stores:

- a metadata-stripped normalized RGB PNG;
- raw little-endian float32 depth at source-normalized dimensions;
- a percentile-normalized 8-bit depth PNG with a light bilateral filter;
- a manifest with adapter/model provenance, parameters, checksums, device, timings, and
  available memory measurements.

Cache keys include the normalized source hash, preprocessing and pipeline versions,
adapter/model identity, pinned weight checksum, device, percentile range, and smoothing
parameters. A per-key process lock serializes writers; cache entries are published as
whole directories. Reads verify artifact checksums, dimensions, image modes, and raw
depth finiteness before reuse. Invalid entries are rebuilt. The fake adapter makes the
same normalization, post-processing, cache, and output path usable without model
weights. A cache manifest retains the metadata from the source that created its assets;
each preparation result reports dimensions and normalization warnings for its current
input, including on a cache hit.

`pnpm test:depth` runs the Python worker tests for EXIF orientation, supported image
formats, alpha/grayscale and extreme aspect ratios, cache reuse and invalidation,
corrupt assets, and stable invalid-input and invalid-depth failures.

The contact-sheet command prepares every entry from the supplied manifest and writes
source/depth comparisons plus a JSON report with per-image failures and metrics. The
repository currently has zero corpus entries, so its corpus-wide model evaluation and
visual review cannot be completed yet. Running the command against the current
manifest creates a labeled pending sheet rather than implying review has passed.

Stable failures include `INPUT_UNREADABLE`, `INPUT_FORMAT_UNSUPPORTED`,
`INPUT_DIMENSIONS_INVALID`, `INPUT_DECODE_FAILED`, `DEPTH_INFERENCE_FAILED`,
`DEPTH_OUTPUT_INVALID`, `DEPTH_RANGE_INVALID`, `DEPTH_POSTPROCESS_FAILED`, and
`OUTPUT_WRITE_FAILED`. Corpus-sheet failures use `CORPUS_MANIFEST_INVALID`,
`CORPUS_ENTRY_INVALID`, or `PREPARATION_FAILED` as appropriate.

The model revision and weight checksum are documented in
[`v0.2-depth-model.md`](./v0.2-depth-model.md). No renderer, segmentation, inpainting,
or alternative depth model is included in this milestone.

A 2026-09-24 CPU smoke run on a synthetic 32×24 PNG produced validated assets with the
pinned real model and then reused them on a second request (`miss` followed by `hit`).
This checks the model-loading path; frozen-corpus review remains outstanding.
