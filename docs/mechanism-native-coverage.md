# Native cohort registry and coverage

The version2 [native board](./mechanism-shorts-ms3-native-coverage-board.json)
registers the actual selected assets and controller contracts for EU001–EU010.
The [generated schema](./schemas/mechanism/native-coverage-board.schema.json)
and `scripts/mechanism/native-coverage-board.ts` admit generic native families;
the historical three-family board and registry remain source-bound history.

Each row retains the frozen question, explanation/design and fact references,
registry identity, declared route, asset/rig work and pinned JSON work evidence.
The command rehashes the frozen selection, preserves channel order and requires
exactly the selected IDs in the board, native queue and current reports. It checks
current source/controller/plan pins, the selected WAV identity, original1×
duration/sample clock and1080×1920/30fps selection format. It uses the production report reader to verify
sealed products and artifact-specific reviews without executing, retrying or
repairing a job. Run it after production has released the queue lock.

```sh
node --import tsx scripts/mechanism/native-coverage-board.ts \
  docs/mechanism-shorts-ms3-native-coverage-board.json \
  /path/to/queue.json /path/to/output \
  /Applications/Blender.app/Contents/MacOS/Blender \
  /path/to/coverage-report.json
```

The output file contains individual rows, the revised denominator, route totals,
distinct registered asset identities/families, declared new asset versions/rig
types and separately admitted extension counts. Standard output is one small
path/count receipt. The report destination must be new; immutable publication
prevents overwriting a board, queue, source, evidence or earlier report. The auditor does not generate media or spend provider credits.
Board/selection/work/source/report JSON is bounded at4MiB per file and300 rows;
existing production input, artifact, memory and execution bounds still apply.

The selected board discloses two asset identity revisions (zipper and buckle),
eight unchanged intake asset identities and zero declared new native rig types.
Those are source-bound work declarations, not physical or positive library
qualification. Aliases do not inflate distinct asset-version counts. Future work
must revise the board and supply its work evidence; recolors or camera changes
cannot add selected episodes.

Positive support requires current verified products and all six complete
artifact-specific QA dimensions passed. Imported catalog readiness, declared work,
encoding, sampled pictures and a not-applicable decision do not satisfy this
actual narrated pilot's whole-review requirements. Unreviewed/stale/failed rows
remain unsupported. Missing effort telemetry retains null savings; this command
does not reinterpret original first-pass provenance or grant human acceptance.

Current full all-ten audit and independent installed/receiving/software gates
remain open. [Acceptance tracker](./mechanism-shorts-ms3-acceptance.md).
