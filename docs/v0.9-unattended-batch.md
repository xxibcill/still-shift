# v0.9 unattended batch execution

The batch CLI accepts newline-delimited JSON requests and renders independent 3–8 second clips through the same v0.8 WebGL engine. It bounds concurrent renders to two, records one ordered result per input, continues past item failures, and produces a final summary. Its per-item checkpoint holds the exact `AnimationResult`, so successful retries retain the same timing, scene decision, output hash, and metrics. Request, source, scene, and output hashes are verified before reuse.

See [the CLI usage guide](../tools/still-shift-cli/README.md#unattended-batch) for the input format, output layout, exit codes, and retry behavior.

## Verification

- `pnpm lint`, `pnpm build`, and the full `pnpm test` suite pass.
- `pnpm test:browser:batch` covers two rendered items and one unreadable source, then repeats the manifest and verifies both completed items are reused unchanged. It also tampers with one MP4 and confirms only that item fails validation.
- `pnpm test:browser:cli` keeps the single-image contract green.
- On 2026-09-24, a 50-item technical batch from 43 private candidate stills and seven repeated inputs finished unattended: 50/50 valid MP4 results, 46 without warnings, four with warnings, zero 2D fallbacks, zero failures, and 186.3 seconds elapsed at concurrency two. Median per-item wall time was 7.42 seconds for a three-second clip; p95 was 7.88 seconds. Nine warnings were emitted across four clips (four edge-risk, four motion-clamp, one lateral-reduction). The outputs totalled 88.4 MB.
- Retrying the same manifest reused all 50 checkpointed results in 0.157 seconds with no rendering. This measures technical completion and cache reuse; it is not the frozen representative corpus and cannot satisfy the human acceptance gate.
