episode fixture is not the implementation source. The inventory records the ZIP,
original scene sources, narration takes, uncompressed mixes, cue/caption files,

## Initial package and resource boundaries

Keep scene/asset/rig/sidecar contracts in `scene-contract`; pure rigid evaluation
and native graph/backend support in `renderer-core`; preparation and episode
orchestration in `animation-engine`; authoring helpers in `motion-builder`; commands
in `still-shift-cli`. Reuse the browser/process/output boundaries in
`execution-runtime`. No new package is needed for the first vertical slice.

The initial shared scene convention is right-handed, Y-up, with an explicit unit
and conversion from historical E01 Z-up. A frame evaluation consumes time, controls,
parameters and seed and produces transforms, camera, named anchors and analytic
assertions without prior playback. Capture plates and sidecars are derived artifacts.

MS1 begins with procedural E01 geometry and local immutable inputs. Imported binary
assets are rejected until their supported subset is implemented and tested. MS1N
adds bounded indexed rigid meshes/normals/material slots; MS2 expands to the stated
glTF/GLB subset. Skins, morphs, animation, compression and unsupported material or
extension data must yield located errors rather than silently flattened results.

Use one capture worker initially and the existing pinned `chromium-software-2`
profile. Preserve the current 1080×1920, 30 fps, 696-frame E01 comparison. Start
with limits of 128 rigid parts, 100,000 vertices, 200,000 triangles, 64 anchors and
32 material slots per scene, two shadow lights and a 2048-pixel shadow map ceiling.
These are provisional admission limits, not measured capacity or appearance claims.
Profile a one-frame proof and short contact shot before the full episode; record
timings, peak RSS, GPU profile, decoded storage and failures. E01 plates alone are
5,772,902,400 bytes (about 5.38 GiB) as raw RGBA; PNG compression is measured later.
Use the existing 8 GiB application admission budget, without claiming it bounds
process-tree RSS. Raise concurrency only after measured memory and throughput.

Bridge output is explicitly tagged sRGB RGBA PNG plus `composition-sequence-1`
media manifests and a versioned anchor/visibility sidecar. Apply tone mapping once.
Native MS1N must reuse scene/rig/camera identity and explicitly state its depth,
transparency and material subset. Unsupported Canvas native meshes and mixed-layer
combinations fail with located diagnostics. Do not close CE8-L-F by association.

Freeze comparison policy before either renderer implementation: identical shared
geometry/controls/timestamps must resolve within 1e-8 scene units, and independently
projected anchors within 0.5 output pixels. Repeated pinned bridge/native exports
must retain exact hashes within each route. Preview/export captures on the same
route/profile allow at most one 8-bit channel step. Historical hardware v008 and
new software exports use silhouette/contact/anchor and separate rubric comparison;
unrecorded old drivers prevent a bit-exact historical pixel claim. Bridge/native
material differences are reported with images and an explicit acceptance status,
not hidden by an image-wide similarity score.

## Frozen visual and explanation rubric

Assess full-resolution final files and 360×640 phone-size samples with the following
independent dimensions. Each has `pass`, `fail`, `not-reviewed` or `not-applicable`,
a method, interval, evidence link and artifact hash. An export cannot green all rows.

| Dimension          | Required visible evidence                                                                                                                                             |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Recognition        | Tape housing, blade, hook and stationary blade-mounted rivets recognizable at entry and return.                                                                       |
| Solid geometry     | Side faces, real through-slots, curved blade and coherent bevel silhouette from required views.                                                                       |
| Material/light     | Separate metal/plastic treatment, readable bevel highlights/reflection, contact shadow; no double tone mapping or alpha fringe.                                       |
| Mechanical truth   | Fixed mounts, hook travel derived from thickness, legal stops and selected contact surfaces; independent analytic expectations every relevant frame.                  |
| Causal explanation | Approach, contact/stop, measurement and return show the relationship rather than hiding it behind camera or labels.                                                   |
| Framing            | Decisive surface inside view during proof; no clipping or unintended cut/camera jump; enlarged views qualified.                                                       |
| Labels/captions    | Exact-copy covered cut, correct semantic target/leader endpoint, safe bounds, no competing overlap, intact value/unit/qualification group.                            |
| Reading            | Each of seven active E01 labels has at least 30 consecutive fully readable frames; copy-specific minimum can exceed that floor.                                       |
| Continuous motion  | Full playback at target fps confirms pacing, continuity, smooth contact and holds; sampled images are insufficient.                                                   |
| Listening/sync     | Unchanged source speech samples, understandable narration, restrained sound and correct terminal audio/video clocks; decode checks and listening recorded separately. |

Sample shot entry/mid/exit, contact event neighborhoods and both sides of each cut.
Store per-frame assertions and label bounds. Independent preview captures and
repeated exports use the declared parity tolerance. Preserve all existing frozen
composition baselines.

## Comparable baseline tasks and telemetry

Freeze task definitions before measuring reuse: (1) produce a complete E01 contact
shot; (2) change TRAVEL copy and repair an injected overlap; (3) change a compatible
geometry dimension and camera target; (4) replace narration with a shorter original
take and recompile timing. Pair baseline and system attempts at the same quality,
resolution, factual complexity, supplied input set and delivered completeness.
Historical ad hoc captures are context, not a measured token baseline.

For every attempt record episode/task ID, source/asset/profile versions, model and
provider, start/end timestamps, submitted revision, setup or routine category,
input/output/cached-input tokens when actually available, active creator minutes,
stage durations, source edits, tool calls, retries/repairs, render work, plate cache
hits/misses, output bytes, first failure and exact accepted artifact. Tokens and
active creator time are `null` when unavailable. Wall time is not active labor.
Retain failed attempts and disclose learning or provider changes.

First-pass technical success means the first submitted job completes required
technical checks without repair, retry or manual recovery. Encoding alone does
not qualify. Reviewed-ready requires review on the current artifact hash; an
affected edit invalidates its prior review.

Report setup separately from recurring effort and asset/family onboarding. Use
medians for the MS3 routine-token target, totals/means for cost projections and
nearest-rank percentiles for the ten-row cohort (`ceil(p × n)`, 1-based index).
Publish individual rows; ten-row p95 is coarse. Empty denominators and missing
telemetry remain unavailable. Do not assert savings until comparable data exists.
