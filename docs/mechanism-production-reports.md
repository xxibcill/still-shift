# Production report foundation

The public engine exports `MechanismProductionEpisodeReportSchema`,
`MechanismProductionQASchema`, `createUnreviewedMechanismQA`,
`inspectMechanismProductionDisposition` and `summarizeMechanismProductionCohort`.
These are data validation and pure summary helpers. The durable controller and
real native executor now retain attempts and artifact-bound technical full-decode
QA. [Registered semantic and warning helpers](./mechanism-production-semantic.md)
have separate actual-sample proof. The [report command](./mechanism-production-report-command.md)
now connects actual native products to bounded episode/cohort reports. Semantic/
warning integration, broader QA and positive pilot admission remain in development.

An episode report names its question, family/design, input/output/code/profile
hashes and output-frame/source-sample clocks. It retains contiguous original
attempt numbers and passed/failed/cancelled/interrupted outcomes. Six separate
QA dimensions record method, evaluated interval, evidence artifacts and reviewer
kind. An unreviewed dimension has no fabricated interval or completed-review
metadata. Automated checks cannot declare continuous playback, listening or
factual review passed.

A changed input, output, code or profile invalidates the old reviews for readiness;
raw prior evidence remains available. Current intervals cannot exceed their clocks.
Whole-artifact technical/mechanical/continuous/listening/factual readiness needs
complete intervals with the proper units. Sampled visual evidence retains its
scoped method; it does not certify every encoded glyph or continuous frame.
Mechanical failure counts prevent reviewed-ready state. Reviewer metadata is a
recorded declaration, not automatic proof that a person listened or watched.
The queue controller validates actual artifact bytes and identities. Native
execution supplies its current source/cache/output checks and complete decode;
review declarations still require their own artifact-specific evidence.

Cohort summaries retain individual rows, failures/repeated failures, review counts,
selected versus attempted counts and measurement availability. Distinct IDs and
normalized literal questions are required; the frozen pilot board supplies its
separate semantic/selection contract. p50/p95 use linear interpolation at(n−1)×p.
Missing timings, including interrupted-attempt duration, remainnull. Running first
attempts do not become completed first-pass measurements. First-pass targets remain unavailable while selected
rows are unattempted. Token savings requires retained evidence and comparable
paired measurements for every selected task; setup/routine fields stay separate.
No unit-fixture value is a real pilot metric.

See the [finite MS3 tracker](./mechanism-shorts-ms3-acceptance.md) and
[run evidence](./mechanism-shorts-ms3-results.json). Structural field/row bounds
alone do not qualify file-I/O budgets, managed-memory admission, renderer output,
physical RSS, real review or production acceptance.
